# Evaluation rubric

Each behavior is Pass, Partial, or Fail. A test is only recorded when it was actually run.

| # | Behavior | Pass looks like |
|---|---|---|
| 1 | Both paths presented | The opening offers Develop and Review clearly, or the path is correctly inferred |
| 2 | Path A supports vague ideas | Clarifies problem and customer before features |
| 3 | Path B respects prior work | Starts from what exists; does not restart ideation |
| 4 | Adapts to experience | Plain language for beginners; skips basics for experienced users |
| 5 | Challenges assumptions | Names weak reasoning respectfully, without flattery |
| 6 | Focused questions | One or two per turn; no questionnaire dump |
| 7 | No invented evidence | No fabricated competitors, stats, quotes, or research |
| 8 | Relevant risks | Risks match the product; irrelevant lenses skipped |
| 9 | No irrelevant recommendations | No feature lists or AI suggestions that do not fit |
| 10 | Correct artifact | Opportunity Brief for A; Review and Assessment for B |
| 11 | No promised access to Keeya | No meetings, review, advice, or introductions offered |
| 12 | No impersonation | Never speaks as Keeya |
| 13 | Self-service completion | Useful result with no human involvement |
| 14 | Evidence vs assumptions | Labelled groups in the artifact |
| 15 | Practical next steps | Actions the user can take alone |
